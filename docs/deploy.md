# 部署：PVE LXC + Docker + NFS（只读）

结构：

```
NAS ──NFS(只读)──> PVE 宿主机 /mnt/nas-assets
                     └─ bind mount(ro) ──> LXC /mnt/assets
                                             └─ docker volume(ro) ──> 容器 /assets
LXC 本地盘 ──> docker 卷 asset-data ──> 容器 /data（索引 + 缩略图）
```

两个容器共用一个镜像：
- `web`：网页和 API，端口 8000。
- `scanner`：每 6 小时扫描一次。

从 PVE 到容器这一侧全程只读，索引和缩略图只写在 LXC 本地盘上。NAS 那边也要做相应配置（见第 1 步），否则这里的只读只是"本机不写"，挡不住局域网里的其他机器。SQLite 的 WAL 和扫描锁在 NFS 上不可靠，所以数据卷不能放到 NAS。

每一步后面都附了检查命令，检查通过再做下一步。

## 1. PVE 宿主机：挂载 NAS（只读）

先在 **NAS 上**设置这个 NFS 导出：
- **只读**（RO）。
- 允许的客户端**只填 PVE 宿主机的 IP**，不要填 `*` 或整个网段。NFSv3 不验证客户端声称的用户身份，开放给整个网段等于开放给所有设备。

然后在宿主机上挂载，而不是在 LXC 里挂。非特权 LXC 不能自己挂 NFS。

```bash
mkdir -p /mnt/nas-assets
# /etc/fstab 加一行（按你的 NAS 地址和导出路径改）：
# nas.lan:/volume1/assets  /mnt/nas-assets  nfs  ro,nosuid,nodev,noexec,soft,timeo=150,retrans=3,_netdev  0  0
mount /mnt/nas-assets
```

选 `soft`，是为了 NAS 掉线时让读取报错，而不是让扫描永远卡住。这里只读，报错只会让这一轮扫描跳过，不会损坏数据。

检查：

```bash
ls /mnt/nas-assets | head
```

## 2. 创建 LXC 并开启 Docker 所需特性

1. 用 Debian 12 模板创建一个**非特权** LXC。
   - 内存至少 6 GB：web 2 GB，scanner 3 GB，再留出余量。swap 设为 0。这个 LXC 的内存上限是最后一道防线，第 6 步会说明原因。
   - 系统盘按缩略图上限 4 GB 加索引来定，建议 20 GB 以上。
2. 在宿主机上执行（`<ID>` 是 LXC 编号）：

```bash
pct set <ID> -features nesting=1,keyctl=1
pct set <ID> -mp0 /mnt/nas-assets,mp=/mnt/assets,ro=1
pct reboot <ID>
```

`nesting` 和 `keyctl` 会削弱 LXC 的隔离，这是在 LXC 里跑 Docker 的代价。所以这台 LXC 只用来跑这个服务，不要放别的东西。

检查（LXC 里）：

```bash
ls /mnt/assets | head          # 能看到素材
touch /mnt/assets/x            # 应该失败：Read-only file system
```

## 3. 权限：UID 映射

非特权 LXC 的 UID 在宿主机上会整体偏移 100000。容器里的 `app` 用户（uid 1000）在宿主机和 NAS 看来是 **uid 101000**。

所以 NAS 上的素材必须对这个 uid 可读。二选一：
- 文件对"其他人"可读（文件 `r`，目录 `r-x`）。大多数 NAS 默认就是这样。
- 或者在 NAS 的 NFS 导出里设置 squash：把所有用户映射到一个**专用账号**，这个账号在 NAS 上只对素材共享有只读权限。可以用 guest 或单独建一个账号，**不要映射成 admin**。

优先用第一种。

检查（宿主机上，模拟容器用户）：

```bash
setpriv --reuid=101000 --regid=101000 --clear-groups ls /mnt/nas-assets | head
```

`101000` 是默认映射下的值。如果给这个 LXC 配过自定义 `lxc.idmap`，按实际映射换算。

这条能列出文件就没问题。如果报 `Permission denied`，先改 NAS 的权限或 squash 设置，再继续。

## 4. LXC 里安装 Docker

按 Docker 官方文档在 Debian 上安装：https://docs.docker.com/engine/install/debian/

需要装 `docker-ce` 和 `docker-compose-plugin`。不要用 Debian 自带的 `docker-compose` v1。

检查：

```bash
docker run --rm hello-world
docker compose version
```

## 5. 部署

把项目目录拷到 LXC，比如 `/opt/assetindex`，然后：

```bash
cd /opt/assetindex
cp .env.example .env
nano .env               # 确认 ASSET_NAS_PATH 和 ASSET_ROOTS；ASSET_BIND 默认 0.0.0.0（所有网卡）
docker compose build
docker compose run --rm web python -m assetindex check
docker compose run --rm web touch /assets/x     # 应该失败：Read-only file system
```

`check` 每一行都应该是 `OK`：

| 检查项 | 失败时 |
|---|---|
| data dir writable | 数据卷权限不对 |
| database | SQLite 打不开；看报错 |
| root … readable | NAS 没挂上，或 uid 101000 读不了（见第 3 步） |
| bsdtar | 镜像里缺 libarchive-tools（不该发生） |
| bsdtar non-ASCII names | 中文包内文件名匹配失败：locale 问题，把输出发给我 |
| 3D viewer files | 前端文件缺失或 MIME 不对 |

全部 OK 后启动：

```bash
docker compose up -d
docker compose logs -f scanner     # 首次扫描：看到 "thumbnail cache: removed" 就是扫完一轮
```

启动（包括重启、更新）时不会自动扫描。第一次装好后，在网页任务栏「扫描」一行点「立即扫描」开始首次扫描，同一行会显示扫到哪一步、进度多少。之后定时扫描接着上一次扫描的时间走，默认每 6 小时一次（`SCAN_INTERVAL_SECONDS`）；如果停机期间错过了，就从启动时起重新计时。

检查网页和 3D 预览需要的 JS：

```bash
curl -sI http://localhost:8000/ | head -1
curl -sI http://localhost:8000/vendor/three/build/three.module.min.js | grep -i content-type   # 应含 javascript
```

浏览器打开 `http://<LXC 的 IP>:8000`。

## 6. 确认内存上限真的生效

在嵌套的 LXC 里，Docker 不一定能设置内存限制，要实际确认：

```bash
docker stats --no-stream
```

`MEM USAGE / LIMIT` 那一列应显示 2GiB（web）和 3GiB（scanner）。

如果显示的是整个 LXC 的内存，说明限制没生效。这时只能靠 LXC 本身的内存上限兜底。最坏情况是两个容器一起被杀，然后被 `restart: unless-stopped` 拉起来。把输出发给我，我们再看怎么处理。

## 日常操作

| 要做的事 | 命令 |
|---|---|
| 立刻扫一次 | 网页任务栏「扫描」一行点「立即扫描」，或 `docker compose exec scanner python -m assetindex scan` |
| 停止扫描 | 任务栏「扫描」一行点「停止」：处理完手上这个文件夹、压缩包或这批向量就停。已扫的保留，没扫完的下一轮定时扫描接着做 |
| 重试坏包和没封面的包 | `docker compose exec scanner python -m assetindex scan --retry-errors` |
| 看扫描日志 | `docker compose logs --tail 100 scanner` |
| 升级 | 网页任务栏「更新」一行点「更新」（需先装一次更新服务，见下文）；或手动 `git pull && docker compose up -d --build` |
| 重建索引 | `docker compose down && docker volume rm assetindex_asset-data && docker compose up -d` |

- 定时扫描正在跑时，手动扫描会直接退出（退出码 3，日志里有 "another scan is running"），等它跑完再试。
- 某个包连续两次把扫描进程撑爆内存，会被标记为坏包并跳过，日志里能看到 "killed the scanner"。调高 `SCANNER_MEM_LIMIT` 后，用 `--retry-errors` 重试。
- 索引数据卷可以随时删掉重建，只是要重新跑一遍首次扫描。NAS 上的东西不受任何影响。

## 网页一键更新

页面任务栏里的「更新」一行会显示当前版本和 GitHub 上的新提交，点「更新」就会自动拉代码、重建并重启容器，不用再 ssh 上去。

真正执行更新的是 LXC 主机上一个很小的 systemd 服务，容器本身拿不到 Docker 的控制权。这个服务只需在 LXC 里装一次，前提是容器已经在运行：

```bash
cd /opt/asset_store            # 你 clone 仓库的位置
sudo deploy/updater/install.sh
```

它会做这些事：

- 从正在运行的 web 容器上找出数据卷在主机上的路径；
- 安装 `asset-updater.path`（网页一提交请求就执行更新）和 `asset-updater-check.timer`（每小时 `git fetch` 一次，看有没有新版本）；
- 以仓库所有者的身份执行 git 命令，用的是你平时 `git pull` 时的凭据；`docker compose` 以 root 身份执行。

说明：

- 更新执行的是 `git pull --ff-only` 加 `docker compose up -d --build`。如果 LXC 里的仓库有本地改动或分叉，pull 会失败，页面上显示红点，鼠标悬停能看到报错。完整输出在数据卷里的 `update.log`。
- 重建期间网页会断开一会儿，完成后页面自动刷新到新版本。正在跑的扫描或看图描述会被打断，重启后点一下就能接着做，已经完成的部分不会丢。
- 拉代码和重建镜像期间可以点「停止」，服务继续跑原来的版本。进入「重启服务」这一步后就不能停了，免得网页起不来。停止功能从装上这个版本之后的下一次更新开始生效（主机上的更新脚本在每次更新成功后自动换成新的）。
- 卸载：`sudo deploy/updater/install.sh --uninstall`。
- 查看服务日志：`journalctl -u asset-updater -u asset-updater-check`。

## 看图模型

「看图描述」和「素材整理」用同一个能看图的对话模型（OpenAI 兼容的 `/chat/completions`，比如 Strata 上的 Qwen）。

1. 网页右上角点「设置」，填写：
   - 接口地址：填到 `/v1` 为止，例如 `http://192.168.1.234:8080/v1`，程序会自动加上 `/chat/completions`；
   - 模型名：Strata 不看这个字段，随便填；其他服务要填真实的模型名；
   - API key。
2. 点「保存」，再点「测试」。模型会描述一张红色圆形的示例图，返回内容和耗时都会显示出来。

说明：

- **任务参数**（同一个对话框里，下次开始任务时生效）：
  - 并行数量（默认 3）：素材整理同时向模型发几个问题。模型服务器一次只算一个的话，多出来的只是排队，整体只快一点；要真正提速，得在模型服务器上开并行（比如 llama.cpp 的 `--parallel 3`，同时把 `-c` 乘 3），并把这里设成同样的数。
  - 接口出错重试次数（默认 3）、重试前等待（默认 10 秒）：素材整理遇到接口连不上、超时时，同一个包最多再问几次、每次出错后等多久再发新问题。
  - 连续失败上限（默认 100）：连续失败这么多次就停止任务，看图描述和素材整理都用。
- **key 的存放**：保存在数据卷的 `caption.json` 里（权限 600），网页上不会再显示。没有登录，局域网里的人都能改这些设置；为了不让别人把 key 骗到他自己的机器上，改了接口地址就必须重新填 key。

## 语义搜索（向量模型）

首页搜索框按资源包搜索时，除了文字匹配，还会按意思找（比如「蒸汽朋克俯视角RPG」）。这需要一个 OpenAI 兼容的 `/embeddings` 接口，比如 Ollama 上的 `bge-m3`。

1. 右上角「设置」→「语义搜索（向量模型）」：勾选「启用」，填接口地址（例如 `http://192.168.1.10:11434/v1`，程序会自动加上 `/embeddings`）、模型名，需要的话填 API key。
2. 图片格式：只用文字就选「不发送图片」；模型能直接收图片时，按它的接口格式选。
3. 点「保存」，再点「测试连接」，成功会显示向量维数。
4. 向量在扫描时计算：点「扫描」可以马上开始。对话框下方显示进度。

说明：

- 换了模型，所有向量都要重新算。
- key 保存在数据卷的 `embedding.json` 里，网页上不会再显示。改了接口地址就必须重新填 key（原因同上）。
- 没启用时扫描不计算向量，搜索只按文字匹配。

## 看图描述（可选）

让一个能看图的对话模型（OpenAI 兼容的 `/chat/completions`，比如 Strata 上的 Qwen）给图片写一句中文描述和几个关键词。写好以后，搜索框能按画面内容搜到图片（比如搜「宝箱」「爆炸」）。模型在上面「看图模型」里设置。

它由单独的 `captioner` 容器执行，平时空闲。**只有在网页上点「开始」才会运行**，定时扫描不会触发它。

1. 先在右上角「设置」里设置好看图模型（见「看图模型」一节）。没设置时，开始按钮是灰的。
2. 网页任务栏「看图描述」一行点「打开」。
3. 选好根目录和文件夹（留空表示整个根目录，输入时会提示子文件夹），对话框会显示要处理多少张，然后点「开始」。
   - 默认只处理还没有描述的卡片，勾选「已经有描述的也重新描述」就全部重做。
   - 随时可以点「停止」，当前这张描述完就停。已经写好的描述会保留，下次开始时接着处理剩下的。
4. 描述会显示在大图下方的「画面描述」里，鼠标悬停在卡片上也能看到。

说明：

- **速度**：一次只处理一张。本地模型通常每张几秒，几万张第一次要跑好几个小时，期间那台机器上的模型会被占着。建议按文件夹分批跑。
- **发出去的内容**：每张卡片一张 512px 的 JPEG（压缩包发它的拼图），外加固定的提示词。请求里带 `reasoning_effort: "none"`，让模型不先"思考"再回答。
- **出错处理**：
  - 接口连不上或超时：任务立即停止。
  - 单张图被拒绝或模型没回答：这张记为失败，继续下一张。
  - 连续被拒绝的张数达到「连续失败上限」（默认 100）：说明设置有问题，任务停止。
  - 失败的图下次开始时会再试一次。
- **读不出图的卡片**：eps 没有内嵌预览、超过 5000 万像素的超大 JPG 等，没有图可以发，记为失败。
- **看日志**：`docker compose logs --tail 100 captioner`。
- **命令行直接跑**：`docker compose exec captioner python -m assetindex caption --root nas --prefix 某个文件夹`。

## 素材整理（第一步：只出建议）

主页任务栏的「整理」一行点「打开」，进入整理页。分析会做这几件事：

1. **把素材库分成"包"**：压缩包是一个包，文件夹按目录结构判断。
   - 顶层是 `2D`、`3D`、`Audio`、`itch`、`UE` 这类分类名或来源名的，下面每一项各算一个包。
   - 名字里带"合集""系列""Collection"的文件夹，会再往下展开一层。
   - 一个文件夹里（或下一层子文件夹里）有 3 个以上名字不同的压缩包，就当成"放包的文件夹"展开，比如 `UE/道具/` 里每个 `.rar` 各算一个包，再深的层也一样。名字开头都一样的（`Cabin_Unity.zip`、`Cabin_Unreal.zip`，或者 `4.27/`、`5.0/` 里放同一个包）算同一个包的几个版本，不展开。
   - 和压缩包同名的预览图、说明文件（`Castle.rar` 旁边的 `Castle.png`），以及分卷（`x.part1.rar`、`x.part2.rar`），跟压缩包算同一个包，一起移动。名字里的空格、下划线、大小写、版本号不影响配对。专门放预览图的子文件夹（比如 `PM895/JPEG/(1)_xx.jpg` 对应 `PM895/(1)_xx.zip`，里面全是和上层压缩包同名的图）也一样，图跟着各自的压缩包走。
   - 判断错了，在页面上点「拆开」，这个包的子项就会各自成为一个包；点「合并」，它所在的整个文件夹就当成一个包。
   - 已经确认或拒绝过的文件夹包，规则改了也不会被拆开。
2. **查重**：只看大小撞车、256KB 以上的文件。先「抽样比对」：每个文件只读开头、中间、结尾各 16KB；抽样也一样、而且所在的包文件数和总大小都和另一个包相同的，才「细比」读整个文件。样例里要读的数据从 2.2GB 降到 62MB。结果按文件缓存，下次只看新增或改过的。完全相同的包，多出来的副本建议移到 `_Duplicates/`。不同包之间重复的单个文件，以及包内的重复文件，只在顶部统计里列出来，不建议移动，免得把包拆坏。
3. **归类和起名**：用右上角「设置」里的看图模型（比如 Strata 上的 Qwen），把每个包的拼图、文件名和画面描述发给它，让它从目录方案里选一个分类，并起一个「来源 - 内容」形式的名字。原名是纯编号时，编号会保留在新名字后面。

目录方案：

| 目录 | 放什么 |
|---|---|
| `01_2D/Characters` `Environments` `Props` `UI` `VFX` `Textures` | 2D 角色、场景、道具、界面图标字体、特效、贴图 |
| `02_3D/Characters` `Environments` `Props` `Vehicles` `Vegetation` `VFX` `Animations` | 3D 角色、场景、道具、载具、植物、特效（UE Niagara、Unity 粒子等引擎特效）、动作 |
| `03_Audio/Music` `SFX` `Ambient` `Voice` | 音乐、音效、环境音、语音 |
| `04_Tools/Shaders` `Plugins` `Templates` | Shader、引擎插件和工具、项目模板 |
| `05_Reference` | 设定集、原画、照片、教程 |
| `_Unsorted` / `_Duplicates` | 看不出来的 / 重复的副本 |

引擎（Unity、UE）不单独设目录。卡片上本来就有引擎角标，按内容分类之后，同一类的 Unity 包和 UE 包放在一起。

页面上可以：

- 按状态查看（待确认、重复、已确认、已拒绝、未分析、失败），按分类筛选；
- 逐条或批量确认、拒绝，点「改」手动修改目标路径。目标文件夹里已有名字只差格式、标点或「(2)」的压缩包时（比如 `X.rar` 和 `X.zip`），预览图会配错，所以不能用这个名字。自动起名会编号成 `X 2.zip`，不用 `X (2).zip`，因为 `X (2).png` 会被当成 `X.zip` 的第二张预览图；
- 在重复的几份里点「改为保留这份」；
- 在分类下拉里选一个分类后，会出现「确认这个分类全部（N 个）」：确认当前列出的全部包（连同搜索框的筛选），不只本页。适合每个分类抽查几个没问题后整批确认。「未分类」不能整批确认，要一个个看。确认后马上移动（见下一节）。
- 不要的包点「标为待删除」：它会被确认并马上移到 `_待删除/`（重名自动编号）。程序不删文件，你在群晖 File Station 里检查后再删，那样能进回收站（通过 NFS 删除的不进回收站）。`_待删除/` 里的包不再分析、也不参加查重。
- 带密码的 7z（扫描读不出里面的文件）会在「执行整理」下面列出来。填上解压密码，点「全部解开」后：
  - 每个包解成同名文件夹；包里只有一个顶层文件夹时，直接用这个文件夹；
  - 解完核对文件数和总大小，对得上才算数；
  - 预览图放进这个文件夹，原压缩包移到 `_待删除/`；
  - 密码不对的包原样留着；NAS 剩余空间不到 20 GB 时停下；
  - 解完会自动扫描一次，再在整理页「开始分析」，给新文件夹出建议。
  
  密码只用这一次，不保存。已经标为待删除的包不解开。
- 「执行整理」下面的「待删除」显示 `_待删除/` 里有多少文件、多大。点「永久删除」并输入「删除」两个字后，mover 会删掉 `_待删除/` 里的所有文件和空文件夹，删完自动扫描一次。
  - 这里删除是通过 NFS 直接删，**不进群晖回收站**，删了就找不回来。
  - 想留后路，就在 File Station 里删，那样会进回收站。
- 点「重新分析」（或勾选后点「重新分析选中」）清掉建议，下次开始分析时重新问模型，适合改了分类方案或提示词之后。已确认的包和重复包不受影响。
- 点「拆开」把一个文件夹包拆成几个包；点「合并」把一个包所在的文件夹整个当成一个包（里面有确认或拒绝过的包时不让合并，先撤回）。

说明：

- **分析不会移动任何文件；确认就会马上移动**（包括改目标、标为待删除），见下一节。
- `_下载` 里的新包（下载、上传进来的）不用手动开始：每次扫描完，只要有从没分析过的，就自动排一次 `_下载` 的分析，打开整理页就能看到建议。模型答不出的包不自动重试，要在整理页手动开始分析。没设置看图模型时不排。
- 分析由 `captioner` 容器执行，和看图描述共用同一个模型，同一时间只跑一个任务；两个都提交了，就排队。
- 模型接口出错（连不上、超时、重启中）时，这个包放回队列，等一会儿再问，不算它失败（同一个包重试到上限还出错，才记为失败，免得一个包把模型卡住还拖住别的包）；模型答不出分类的包记为失败，继续下一个。两种失败连续达到上限才停止，所以重启模型服务器不会打断分析。次数和等待时间都在「看图模型」的任务参数里设置（默认重试 3 次、等 10 秒、连续 100 次停止）。
- 每个包要问一次模型，大约和描述一张图一样慢。可以先填一个文件夹，分批分析。
- 整理页和主页任务栏都可以点「停止」，手上这个包问完就停，已经出的建议会保留。
- 只有一个文件的包（一个压缩包、一张图），如果还没有看图描述，会在归类的同一次提问里顺便写好描述，之后跑看图描述时就跳过它，不用再问一次。文件夹包不会这样做。
- 某个包里的文件变了（新增、删除、修改），它的建议会作废，下次分析时重新问。已经确认或拒绝的决定，在文件没变的情况下会一直保留。
- 命令行：`docker compose exec captioner python -m assetindex organize --root nas --prefix 某个文件夹`。

## 素材整理（第二步：执行）

在列表里确认一个建议（或批量确认），mover 马上把这些包移到建议的位置，进度显示在整理页的「执行整理」里。正在移动时又确认的，这批移完后自动接着移。移动出错、被停止，或当时 NAS 只读而没能移动的包，之后点「执行整理」里的「移动已确认的」再移。

1. 有些已确认的包会先不动，原因列在「执行整理」里：
   - 目标已经存在，或者两个包要去同一个地方（不分大小写）；
   - 目标落在另一个要移动的文件夹里；
   - 移动后整个库重新分包，结果和计划不一样（比如一张单独的图会被并进别的压缩包）；
   - 包里的文件在确认之后变了。
2. 移动只移动、不复制：
   - 压缩包的预览图、分卷改成和新名字同名，一起移动，所以移动后还能配上。
   - 文件夹包整个移动。
   - 索引跟着改路径，看图描述、预览、拼图都保留，下次扫描不会当成新文件。
3. 「移动记录」里每次移动都可以「撤销这次」：放回原来的位置，建议回到「待确认」。原来的位置已经被别的文件占了的包不会撤销，会列出来。

安全措施：

- **只有 `mover`、`fetcher`（下载）和 `web`（只用于上传）容器能写 NAS**，而且要在 `.env` 里设 `ASSET_MOVER_ACCESS=rw` 再 `docker compose up -d`。默认是 `ro`，只能看计划、不能下载和上传。扫描、看图描述的容器一直是只读挂载。
- NAS 上的目录要对容器里的用户（uid 1000，可用 `APP_UID` 改）可写。NFS 有 root_squash 或权限不对时，移动会提示「Permission denied」并停下，不会动其他文件。
- 永远不覆盖：移动前检查目标（不分大小写），移动本身也用不会覆盖的方式：文件先建硬链接再删旧名，文件夹先建空目录占住名字再改名。NAS 不支持硬链接时，退回到「检查后改名」。
- 每个包是一个事务：先在 `/data/moves/<时间>.jsonl` 里记下要做的每一步，再动手；一个包里任何一步失败，已经做的会放回去。
- 中途断电、容器被杀：下次移动或扫描前会先收尾，全部移完的补上索引，一个没动的作废，移了一半的放回原处（扫描容器是只读的，只能补索引；需要放回时，整理页会出现「收尾上次中断的移动」按钮）。有没收尾的包时，扫描会暂停，因为扫描会把移动过的文件当成删除再新增，看图描述就丢了。
- 移动时会占住扫描锁和模型锁：扫描或整理分析在跑时，移动排队等它们结束。
- 搬走包之后，原来的文件夹继续当作「放包的文件夹」：剩下的两三个包不会被合并成一个包。

## 下载到素材库

任务栏「下载」→「打开」，贴一个文件的下载链接（http/https 直链），`fetcher` 容器里的 aria2 把它下到根目录的 `_下载` 文件夹，下完自动扫描。之后它和别的包一样，在「整理」里分析、确认、移到分类目录。

- 和移动共用一个开关：`.env` 里 `ASSET_MOVER_ACCESS=rw`。只读时页面会提示，不接受新下载。
- 文件大小不限。服务器先告诉了大小、NAS 剩余空间不够（再留 1GB）时，会直接标成失败。
- 正在下的文件在 `_下载/.partial/<编号>/` 里，扫描会跳过它。更新、重启容器后，没下完的会从断点接着下。
- 下完会和库里同样大小的文件比内容：一模一样的照样保留，标成「库里已有」，删不删你决定。还没扫描入库的文件不在比较范围内，两份一样的下载要等整理时的查重才能发现。
- 失败原因会写在列表里（404、要登录、校验不符、下到的是网页而不是文件等），可以「重试」。网盘分享链接、要登录的网站下不了。
- aria2 只在容器内的 127.0.0.1 上听命令，每次启动换一个随机密钥；BT 和 metalink 一律不跟。

## 上传到素材库

页头「上传」（或任务栏「上传」→「打开」）→「上传文件…」或「上传文件夹…」，也可以把文件、文件夹直接拖到页面上，把自己电脑上的文件传到根目录的 `_下载` 文件夹。一次选几个文件就是几条上传，各自落成一个文件；选一个文件夹就整个作为一个包（保留子文件夹），落成 `_下载/<文件夹名>/`。传完自动扫描。AI 用 skill 的 `upload` 命令也能传。

- 同一个开关：`.env` 里 `ASSET_MOVER_ACCESS=rw`，这时 `web` 容器也以读写方式挂载 NAS（只往 `_下载` 里写上传的文件）。只读时页面会提示，不接受上传。
- 文件大小不限，一个文件夹最多 20000 个文件；开始前先看 NAS 剩余空间（再留 1GB）。
- NAS 放不了的文件名（含 `\ : * ? " < > |`、首尾空格、路径超过 1000 字节或 64 层）页面上直接跳过，其余照传，传完列出跳过了哪些；要传它们就改名后单独再传。
- 传的过程中文件在 `_下载/.partial/<编号>/` 里，扫描会跳过它。一个文件传到一半连接断了或服务器出错，页面自动重传这个文件，最多 3 次。没有续传：中途关页面、一直连不上，这次上传作废，一小时后自动清掉，重新上传即可。也可以在列表里点「取消」马上清掉。
- 以 `.` 开头的隐藏文件和文件夹（`.DS_Store`、`.git` 等）不传。
- 单个文件传完会和库里同样大小的文件比内容，一模一样的标成「库里已有」；文件夹不比。
- 整理正在移动文件时，传完的上传先等着，移动结束后自动放进 `_下载`（页面要开着）。

## 外部素材（Poly Haven、ambientCG、OpenGameArt、itch.io、Sketchfab、Freesound、Poly Pizza、Openverse）

页头「外部素材」打开搜索页：同时搜 Poly Haven 和 ambientCG 的 CC0 免费素材（HDRI、PBR 材质、模型）、OpenGameArt 的素材（2D、3D、音乐、音效），itch.io 某个标签下的免费素材、Sketchfab 的可下载模型、Freesound 的音效、Poly Pizza 的低模，以及 Openverse 汇总的 CC 图片和音频。点卡片看大图和可选规格，点「下载」就进上面的下载队列，下到 `_下载`。每个网站的结果到了就先显示。

- 这些网站只认英文关键词；输入中文时页面会提示。
- 服务器（web 容器）要能上外网：搜索、详情都是服务器去问网站；缩略图和大图由你的浏览器直接从网站的 CDN 加载。
- Poly Haven 没有搜索接口：服务器把它约 2400 个素材的清单缓存 12 小时，在本地按名字、标签、分类匹配。网站连不上时继续用缓存里的旧清单。
- 已经在库里的（文件路径里有这个素材的编号）标「已有」，在下载队列里或下载过的标「已下载」。
- ambientCG 每个规格是一个 zip。Poly Haven 的 HDRI 是一个文件；贴图是「某分辨率某格式的全套贴图」，模型是「某格式加它用到的贴图」（glTF 还有 .bin），这些由多个文件组成，一起下到 `_下载/<素材名 规格>/` 一个文件夹里，模型的贴图在里面的 `textures/`，打开模型就能找到。
- 多文件的下载里每个文件单独记账：哪个文件 aria2 报告下完了才算完成；重启后只补没下完的，丢了进度记录的半截文件删掉重下。任何一个文件失败，整个下载算失败，可以重试。多文件下载落地时不做「库里已有」的比对。
- OpenGameArt 没有接口，服务器读它的搜索页和素材页（按下载量排序）。它要求每 10 秒最多请求一次：服务器排队发请求，搜完马上点开详情可能要等几秒；排队超过 25 秒就报“等一会儿再试”。结果缓存 10 分钟，详情缓存 1 小时。
- OpenGameArt 的授权各不相同（CC0、CC-BY、GPL 等），详情里写着，用之前看原页面的署名要求。每个文件可以单独下，多于一个文件时还有「全部文件」；都下到 `_下载/<素材名 文件名>/` 一个文件夹里。它的素材不标「已有」（编号是英文单词，没法按文件名比对）。
- Sketchfab、Freesound、Poly Pizza 要你自己账号的 key（注册免费），在搜索页右上角「网站账号」里填。key 只存在服务器数据目录的 `external.keys`（只有属主能读），页面只显示“已填/未填”。
- Sketchfab：搜索不要 token，只列作者允许下载的模型；下载要 API token（sketchfab.com → Settings → Password & API）。可选 GLB、glTF、USDZ、原始文件。它的下载链接几分钟就过期，所以队列里只记“哪个模型、哪种格式”，下载器每次开始、重试、断点续传前都用 token 现要一个新链接。授权各异（CC0、CC-BY、CC-BY-NC 等），CC-BY 要署名作者和 Sketchfab，NC 不可商用。
- Freesound：搜索就要 API key（freesound.org/apiv2/apply 申请）。原始文件要 OAuth 登录，程序拿不到，所以能下的是高质量试听版（OGG 约 192kbps、MP3 约 128kbps），下到 `_下载/<声音名 格式>/` 里；要原始文件就点原页面手动下。授权各异，详情里写着是否要署名、能否商用。
- Poly Pizza：搜索、下载都要 API key（poly.pizza/settings/api 新建应用）。每个模型是一个 GLB，CC0 或 CC-BY；CC-BY 的详情里给出现成的署名文字。它的文件服务器也要 key，所以队列里不存 key，下载器开始下载时才把 key 加进请求头。不填关键词时列出 CC0 模型。
- Openverse：不用账号，但不登录每分钟只能请求 20 次、每天 200 次，每页 20 条，所以不填关键词时不请求，结果缓存 10 分钟，点开详情用搜索时拿到的信息、不再请求。图片和音频分两栏。下载的是它原来所在的网站（Flickr、Wikimedia、Jamendo、Freesound 等）给的文件：多数是原图或原曲，来自 Freesound 的声音是 MP3 试听版；个别网站可能拒绝程序下载。授权各异，详情里有署名文字，带“不可商用”的别用在要卖的游戏里。
- itch.io 不让程序搜索和下载：输入的词当作标签（`pixel art` → `pixel-art`），列出这个标签下最受欢迎的免费素材，每页 36 个；不填就列全站的。点开只有封面和简介，要点原页面到 itch.io 上手动下载，下好后放进素材库。

## 给 AI agent 用

`/api/agent/*` 是一组给 agent 用的接口，返回内容精简，每条结果都带下载链接，还能从 zip/rar/7z 里单独取出一个文件。仓库的 `skills/asset-store/` 是配套的 skill：`SKILL.md` 加一个只用 Python 标准库的命令行脚本。

在 Claude Code 里使用：

1. 把 `skills/asset-store` 整个文件夹复制到 `~/.claude/skills/`（所有项目都能用），或者复制到某个项目的 `.claude/skills/`。
2. 设置环境变量 `ASSET_STORE_URL=http://<LXC 的 IP>:8000`。
3. 之后直接说"去素材库找一个火焰爆炸的序列帧放到 Assets/VFX"，agent 会自己搜索、查看缩略图、下载。

别的 agent 可以直接调用 HTTP 接口，接口清单在 `SKILL.md` 末尾，完整文档在服务的 `/docs` 页面。

## 安全

网页**没有登录**，任何能访问端口的人都能浏览和下载全部素材。

只在局域网使用，不要在路由器上做端口转发。需要外网访问时，前面加一个带认证的反向代理，或者走 VPN。
